# Ручная закупка

Подготовленные изменения ещё нужно применить в рабочей базе и опубликовать на GitHub Pages.

1. В Supabase SQL Editor выполнить `stock_manual_purchase.sql`. Старые заявки сохраняются, автоматический расчёт выключается, купленные остаются внизу. Старые «нет в магазине» снова видны как непокупленные. Старая история автозакупок не удаляется.
2. Опубликовать обновлённый `index.html`. Применяйте SQL первым: интерфейс использует новый параметр срочности.
3. Проверить на учётной записи сотрудника: добавить материал, количество, филиал, срочность. Администратор видит код из материалов, ставит/снимает галочку. Галочка не оформляет складской приход; приход оформляется отдельно во вкладке операций.

## Telegram

Обработчик: `supabase/functions/telegram-purchase/index.ts`. Он отвечает только активным чатам из `report_recipients`, использует существующий токен из Vault и показывает только непокупленные заявки. Длинные списки делятся на сообщения.

1. Развернуть функцию в том же Supabase-проекте:
   `supabase functions deploy telegram-purchase --project-ref tmxluzvymwldtxbaiekn --no-verify-jwt`
2. Выполнить `telegram_purchase_setup.sql`: создаёт секрет webhook в Vault и закрытую служебную функцию. Секретный заголовок Telegram заменяет проверку JWT на этом endpoint.
3. Через Bot API `getWebhookInfo` проверить, нет ли уже webhook. Если есть — добавить команду в существующий обработчик, не заменять его. Здесь исходников другого обработчика нет. Если бот использует внешний polling, его также нужно учесть до регистрации webhook.
4. Если других обработчиков нет, выполнить закомментированный блок `setWebhook` в конце SQL. Проверить ответ в `net._http_response` (HTTP 200 и `ok: true`) и состояние через `getWebhookInfo`.
5. Написать боту `/start` из чата, включённого в `report_recipients`. Он отправит актуальную закупку и постоянную кнопку «🛒 Закупка». Нажатие обновляет список; команда `/purchase` работает так же.

Токен и секрет не публиковать в GitHub и не присылать в чат. Изменения не требуют менять токен существующего бота.

## Проверка

`node tests/manual-purchase.cjs` проверяет синтаксис скриптов страницы и поведение списка с подставными данными: сортировку, права на галочки, экспорт, снятие отметки и ошибки записи. Рабочие база и бот проверяются отдельно после применения миграции и развёртывания.
