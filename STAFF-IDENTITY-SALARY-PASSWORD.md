# Личный аккаунт для смены и пароль зарплаты

Сотрудник открывает/подключает смену только на person_id активного staff_accounts своего auth.uid. Первый выбранный участник должен совпадать с аккаунтом. Ранее подключённые участники общей смены сохраняются, новый коллега добавляется только после входа в собственный аккаунт. Для администратора прежние возможности сохранены. Оба RPC открытия и прямые INSERT/UPDATE таблиц смен защищены от подмены сотрудника.

В интерфейсе по умолчанию выбрано своё имя. Чужое имя приводит к сообщению «Войдите в свой аккаунт. Открыть смену на своё имя можно только под своим логином и паролем». Дополнительный сотрудник скрыт для сотрудников; существующий главный по ретуши сохраняется при подключении.

Каждое открытие «Моей зарплаты» запрашивает только пароль. Edge payroll-unlock валидирует текущий JWT через getUser и берёт email на сервере; передать чужой логин нельзя. Пароль проверяется штатным signInWithPassword отдельного непостоянного клиента, его временная сессия закрывается локально, основная сессия сайта сохраняется. Пароль не сохраняется и очищается из поля после попытки. Auth применяет свои ограничения на попытки входа.

Успешная проверка даёт серверное подтверждение на 15 минут для исходного user_id/session_id. Report проверяет действующую auth.sessions и срок; без подтверждения зарплата/штрафы/депозиты не выдаются. В интерфейсе срок 14 минут, затем при пересчёте снова запрашивается пароль. Закрытие окна очищает данные и снимает подтверждение. Администратор пароль дополнительно не вводит.

Миграции staff_shift_identity.sql, staff_shift_write_policies.sql. Проверки tests/staff-identity-salary-lock-rollback.sql, tests/payroll-unlock-edge.cjs, tests/payroll-password-ui.cjs и tests/payroll-ui.cjs. SQL-проверки полностью откатываются, смены сотрудников и реальные пароли не меняются.
