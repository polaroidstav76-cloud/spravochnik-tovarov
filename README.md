# Справочник товаров — бесплатная версия

## Что используется
- GitHub Pages — бесплатная публикация сайта.
- Supabase Free — бесплатная база данных, авторизация и хранение фотографий в пределах лимитов тарифа.
- Сотрудникам нужен только браузер.
- Редактировать товары может только пользователь, вошедший через форму администратора.

## 1. Создайте Supabase
1. Откройте https://supabase.com/ и создайте аккаунт.
2. Создайте новый проект на Free Plan.
3. Откройте SQL Editor.
4. Скопируйте весь файл `supabase.sql` и нажмите Run.
5. Откройте Authentication -> Users -> Add user и создайте администратора (email + пароль).
6. Откройте Project Settings -> API и скопируйте URL проекта и ключ.
7. В файле `config.js` замените:
   SUPABASE_URL
   SUPABASE_ANON_KEY

## 2. Опубликуйте сайт бесплатно
1. Создайте аккаунт GitHub.
2. Создайте PUBLIC repository, например `spravochnik-tovarov`.
3. Загрузите `index.html` и `config.js`.
4. Откройте Settings -> Pages.
5. Source: Deploy from a branch.
6. Branch: main, folder: / (root).
7. Сохраните.
8. GitHub даст адрес вида:
   https://ВАШ_ЛОГИН.github.io/spravochnik-tovarov/

## 3. Работа сотрудников
Дайте сотрудникам только адрес сайта. Они смогут:
- искать товары;
- открывать карточки;
- смотреть фото и описание.

Администратор нажимает «Вход администратора», вводит email и пароль и получает кнопки:
- Добавить товар
- Редактировать
- Удалить
- Обновить

## Шаблоны сообщений
Кнопка «💬 Шаблоны» в блоке «Продажи» открывает готовые ответы для переписки с клиентами в мессенджере.
- Сотрудники ищут шаблон по названию и тексту, фильтруют по категории и копируют весь текст кнопкой «Копировать».
- Администратор (после входа) создаёт, редактирует и удаляет шаблоны.

Перед первым использованием выполните файл `templates.sql` в Supabase (SQL Editor -> Run). Он создаёт таблицу `message_templates` и правила доступа.

## Долги клиентов
Для клиентов, которые платят по расчётному счёту в конце месяца.
- При продаже укажите клубную карту клиента и способ оплаты «Расчётный счёт» (можно частью раздельной оплаты). В отчётах продажа считается оплаченной, а долг автоматически попадает в раздел «📒 Долги клиентов».
- В разделе видны все неоплаченные продажи по каждому клиенту и общая сумма долга. Когда клиент оплатил, отметьте продажи галочками и нажмите «Отметить выбранные оплаченными» или сразу «Все оплачены».
- «Показать оплаченные» выводит историю оплат. Администратор может вернуть ошибочно отмеченную продажу в долг.
- Возвращённые продажи из долгов исчезают.

Таблица и функции описаны в `customer_debts.sql` (уже применено в базе).

## Важно про безопасность
GitHub Pages с GitHub Free требует публичный репозиторий. Поэтому исходный код сайта будет доступен в интернете. Ключ `SUPABASE_ANON_KEY` предназначен для браузера; безопасность данных обеспечивают правила RLS в Supabase.

Не публикуйте в коде пароль администратора или секретный service_role key.

## Если хотите изменить внешний вид
Основные стили находятся внутри `index.html` в секции `<style>`.

## Задания на смену
В «Продажи — настройка» → «Задания» администратор выбирает, кому задание:
- **На филиал** — показывается всем, кто работает на филиале в выбранный день (как раньше).
- **На сотрудника** — показывается этому сотруднику на каждой его смене на любом филиале, начиная с выбранной даты, пока он не нажмёт «Выполнено». Невыполненное задание переходит на следующую смену с пометкой «перенесено».

Во время открытой смены невыполненные задания видны крупной жёлтой панелью внизу экрана во всех окнах. Таблица и функция описаны в `person_tasks.sql` (уже применено в базе).

## Порядок справочников
Администратор перетаскивает карточку справочника мышкой на нужное место, и она закрепляется там (📌 и номер места). Остальные справочники заполняют свободные места по алфавиту. Кнопка «Открепить» возвращает справочник в алфавитный порядок.

## Оплата при получении
В окне продажи есть способ оплаты «При получении (оплата позже)» — для постоянных клиентов, которые платят, когда забирают заказ. Первым идёт блок «Контакт клиента»: Telegram, Max или телефон (обязательно) и номер заказа; клубная карта не обязательна. Такая продажа не попадает в продажи за сегодня и в отчёты, а появляется справа в списке «Ждут оплаты». Когда клиент пришёл, сотрудник нажимает «Клиент пришёл — оплатить», выбирает способ оплаты и клубную карту — только после этого продажа попадает в отчёт текущей смены (номер заказа сохраняется). Заказы старше 2 дней переезжают в «Долги клиентов»: на плитке появляется красный счётчик, при открытии смены выходит напоминание, а при выборе клубной карты клиента программа подсказывает, что у него есть неоплаченный заказ. Отказ клиента — кнопка «Отменить заказ» с причиной. Таблица `pickup_orders`, функции в `kassa_v5.sql`.

## Наличные в кассе
Чтобы завершить смену, сотрудник пишет, сколько наличных остаётся в кассе. При открытии следующей смены филиала программа показывает эту сумму: сотрудник подтверждает её или пишет, сколько лежит по факту. Расхождения видны администратору в «Сводке» и в отчёте за смену.

## Тесты по справочникам
После каждого справочника есть тест (кнопка «Пройти тест» внизу карточки, на карточке значок «📝 тест»). Администратор меняет, добавляет и удаляет вопросы кнопкой «✏️ Вопросы теста» там же и видит последние результаты. Таблицы `guide_questions` и `guide_test_results`.

## Объявления
Кнопка «Объявления» в панели администратора. Объявление показывается при открытии смены, и каждый сотрудник один раз отмечает «прочитал(а)»; кто был на выходном, увидит его в свою смену. Администратор видит, кто уже прочитал.

## Сводка
Кнопка «Сводка» в панели администратора: день, неделя, месяц, квартал или год с выбором филиала. День сравнивается с тем же днём прошлой недели, остальные периоды — с прошлым периодом (если период ещё идёт — с таким же отрезком). Показывает выручку, средний чек, прибыль, выводы, график, что выросло и упало, позиции, категории, сотрудников, филиалы, оплату, дни и часы, контроль наличных, заказов «при получении», долгов и результаты тестов. Функция `admin_period_summary`.

## Склад расходников
Плитка «Склад» в блоке «Смена и деньги». Материал (например «Бумага 10×15 глянец») общий для многих позиций прайса, остаток ведётся отдельно по каждому филиалу.
- **Материалы и нормы** (администратор): название, единица, минимальный остаток и позиции прайса, на которые уходит материал, с нормой на 1 шт. (фото 10×15 — 1 лист, календарь 13 листов — 13). Поиск «10х15» и кнопка «Отметить найденные» привязывают сразу все подходящие позиции.
- **Продажа списывает материал сама** — с филиала, где её оформили. В окне продажи есть поле «Кто выполняет заказ»: если выбрать другой филиал, материал спишется с него. Удалённая продажа возвращает материал, возврат — нет (бумага уже израсходована).
- **Кто выполнил заказ**: продажи за день или по номеру. У каждой позиции можно выбрать филиал, который её печатал, — так заказ делится между филиалами.
- **Приход и перемещение**: приход (закупка, с суммой и поставщиком), перемещение между филиалами, списание брака (с причиной) и инвентаризация (вписываете, сколько насчитали, — разница уходит в журнал). Сотрудник смены работает со своим филиалом; перемещение — с его филиала или на него. Администратор — с любым.
- **Остатки**: таблица материал × филиал, красным — то, что не выше минимума; в подсказке расход за 30 дней и на сколько дней хватит. На плитке «Склад» красный счётчик материалов, которые заканчиваются на вашем филиале, а при открытии смены выходит напоминание с подсказкой, у какого филиала этот материал есть.
- **Журнал**: все движения с фильтрами; администратор может отменить ошибочную операцию.
- **Закупка**: каждый понедельник в 06:00 по Москве собирается таблица, что купить. На каждом филиале должно лежать: расход за неделю плюс минимальный остаток (если минимум не задан — одна упаковка). Расход — среднее за 4 недели (продажи и списания); если одна неделя больше чем вдвое выше среднего остальных (разовый крупный заказ), вместо неё берётся среднее остальных. Заказ округляется до целых упаковок («Сколько в упаковке» у материала). Если материала на филиале 0 — строка «Срочно» вверху таблицы. В таблице наименование, **код для закупки**, упаковки по филиалам, итог, цена упаковки и сумма, внизу общая сумма закупки. Филиал без инвентаризации по материалу не учитывается. Можно скопировать, распечатать, открыть прошлые недели; администратор может пересчитать сейчас. SQL — `stock_purchase.sql`, `stock_packs.sql`.
- **Нормы «на позицию» и расход «на каждую продажу»**: у нормы галочка «на позицию» — списать один раз на строку заказа, сколько бы штук ни было (пакеты для фото 6х9…30х40 уже привязаны так к фото своего размера). У материала поле «Расход на каждую продажу» — списывается с каждой продажи (чековая лента: упаковка = длина рулона в метрах, расход = длина чека, сейчас 0,1 м). Подарочная упаковка (премиум, эконом, для кружки) хранится в мастерской и списывается по своим позициям прайса.

- **Мастерская**: отдельное место хранения, это не филиал, поэтому в кассе, сменах и отчётах её нет. У материала галочка «Хранится в мастерской» (кружки, сувениры): продажа на любом филиале списывает его с мастерской, а «Кто выполнил заказ» его не переносит. В остатках у мастерской своя колонка; приход, списание, инвентаризацию и перемещение можно делать по ней (сотрудник смены — тоже). В закупке такой материал считается по мастерской из продаж всех филиалов. SQL — `workshop.sql`.

Учёт начинается с нуля: после настройки материалов сделайте инвентаризацию на каждом филиале. Таблицы и функции — в `stock.sql` (уже применено в базе).

## Тестовый филиал
Филиал «Тестовый» (в базе `sales_branches.is_test`) нужен, чтобы проверять товары и продажи. Его продажи, возвраты и смены не попадают в «Отчёты», «Сводку», сравнение филиалов и зарплату, продажи на нём не списывают материал со склада, и его нет в остатках и закупке. Продавать на нём можно как обычно. SQL — `test_branch.sql`.

## Вход сотрудников
Сотрудники входят по логину и паролю, администратор — как раньше (email и пароль).
- Логины создаёт администратор: «Управление» → «Логины». Там же меняется пароль, роль, отключается и удаляется доступ.
- Роль «Администратор» видит все разделы, «Сотрудник» — кассу, клубные карты, справочник.
- Логины хранятся в Supabase Auth, роли — в таблице `staff_accounts`; создаёт их функция `supabase/functions/staff-admin`.

Включение в два шага:
1. `staff_auth.sql` — роли (ничего не ломает, касса без входа работает как раньше). Затем выложить сайт и раздать логины.
2. В `config.js` поставить `STAFF_LOGIN_REQUIRED = true` и применить `staff_lockdown.sql`: без входа сотрудника база больше ничего не отдаёт.
