КЛАУДШОП — ШИРОКОФОРМАТНАЯ ПЕЧАТЬ
Версия 0.2 — установка и тестовая проверка

Программа подготовлена для Windows 10/11 и отдельного @perezakazi_bot.
Главное меню: «Широкоформатная печать» и «ДТФ-печать».
Пока подключается только широкоформатная печать; ДТФ явно помечена
как ненастроенная и не принимает файлы. Будущие направления имеют отдельные
очереди; просмотр, отправка и удаление относятся к выбранному разделу.
Перед первым файлом сотрудник обязательно выбирает направление.
Кнопка «Назад» возвращает в главное меню.
Программа подготовлена для Windows 10/11. На вашем компьютере её ещё нужно
установить, подключить бота, Диск и почту и проверить реальную отправку.
Проверка без ваших аккаунтов не подтверждает доставку настоящего письма.

ЧТО ДЕЛАЕТ
• Принимает документы TIF/TIFF/PDF/JPG/PNG размером до 500 МБ.
• Сохраняет оригинальные байты, название, принадлежность к филиалу.
• В 18:00 МСК собирает ZIP, загружает его на ваш Яндекс Диск и отправляет ссылку
  по почте. Первоначальный получатель — ваш тестовый адрес (введите при настройке).
• Уведомляет Telegram после принятия письма почтовым сервером.
  Это не подтверждение, что адресат прочитал письмо или получил его во «Входящие».
• Кнопка «Просмотр файлов» показывает только названия ожидающих файлов.
• Кнопка «Отправить сейчас» отправляет текущую очередь выбранного направления со всех филиалов.
  Она работает даже при выключенной ежедневной отправке — это удобно для теста.
• «Удалить файл» позволяет любому подключённому сотруднику убрать ошибочный файл,
  в том числе во время скачивания, сборки и загрузки ZIP. Архив пересобирается.
• После начала передачи письма SMTP-серверу отменить его уже нельзя. В этот момент
  удаление блокируется. При неоднозначном ответе почты нужен контроль владельца.

Первый запуск НЕ включает автоматическую ежедневную отправку.
Она включается отдельной галочкой после вашего теста.
Не используйте старого бота закупок, сводки или другой действующей системы.

ШАГ 1. УСТАНОВКА
1. Распакуйте ВЕСЬ ZIP в постоянную папку, например C:\CloudshopPrint.
   Не запускайте программу прямо внутри ZIP, из сетевой папки или папки общего доступа.
2. Нужен Python 3.11 или новее для Windows с Tcl/Tk и Python Launcher.
   Официальная страница: https://www.python.org/downloads/windows/
   Пароли и коды подтверждения при установке вводить не требуется.
3. Дважды щёлкните SETUP.cmd. Зависимости находятся в wheelhouse; эта установка
   не скачивает пакеты из интернета. Их версии и SHA256 зафиксированы в requirements.lock.
4. Запустите DIAGNOSTICS.cmd. Он проверит Python, Tk и шифрование Windows DPAPI.
   Не проверяет почту, не отправляет письма и не выводит секреты.
5. Запустите START.cmd. Откроется окно программы.

ШАГ 2. ОТДЕЛЬНЫЙ БОТ
1. В Telegram откройте проверенного @BotFather: https://t.me/BotFather
2. Отправьте /newbot. Задайте имя и username нового бота.
3. Токен скопируйте непосредственно в поле «Токен отдельного бота» в программе.
   Не присылайте токен, API hash, пароль почты или OAuth-токен в чат.
4. Для получения больших файлов программа использует Telegram API через Telethon,
   с авторизацией только БОТА. Это не автоматизация вашего личного Telegram-аккаунта.
   Отдельный локальный Bot API Server и Docker устанавливать не требуется.
5. На https://my.telegram.org/apps войдите самостоятельно и создайте приложение
   в API development tools. Можно назвать его Cloudshop Print Dispatch,
   выбрать Desktop и описание «Приём макетов и отправка заказов фотоцентра».
   Перенесите api_id и api_hash в поля Telegram API ID и Telegram API hash.
   Вход на этом официальном сайте нужен для регистрации приложения. Программа
   не просит номер телефона, пароль личного Telegram или код входа.
   Если Telegram не даёт зарегистрировать приложение — сообщите точный текст ошибки,
   без кодов входа, токенов и API hash; дальше разберём вместе.

ШАГ 3. ЯНДЕКС ДИСК
1. Программа использует уже имеющееся место вашего Диска, подписку не покупает.
   Один макет может весить 500 МБ; предварительно проверьте свободное место.
2. Для REST API нужен OAuth-токен вашего приложения Яндекс Диска.
   Регистрация: https://oauth.yandex.ru/client/new
   Инструкция: https://yandex.ru/dev/disk/rest/
   Запросите права Диска, необходимые для чтения/проверки метаданных, записи,
   публикации архива и удаления созданных программой временных архивов.
   Названия и шаги интерфейса Яндекса могут изменяться; при настройке идём по экрану.
3. Полученный токен введите в программе, в поле «OAuth-токен Яндекс Диска».
4. Архивы создаются в отдельной папке Cloudshop-Print. Для отправки создаётся
   публичная ссылка: любой человек, который её получил, сможет скачать архив.
   Сами файлы из разных филиалов не публикуются по одному.
5. Успешно отправленные архивы и оригиналы автоматически НЕ УДАЛЯЮТСЯ.
   Правила хранения и очистки согласуем после теста. При заполнении диска
   программа оставляет очередь на компьютере и сообщает об ошибке.
   Неотправленный ZIP, состав которого изменили удалением файла, убирается
   из созданной программой папки в корзину Диска и формируется заново.

ШАГ 4. ПОЧТА
1. В поле «Получатель» укажите ваш тестовый почтовый адрес.
2. В поле «Отправитель» укажите свой Яндекс-ящик, с которого
   разрешаете отправку. Вход SMTP должен соответствовать адресу отправителя.
3. В настройках Яндекс ID создайте отдельный пароль приложения для почты:
   https://id.yandex.ru/security/app-passwords
   При необходимости включите доступ почтовых программ в настройках Яндекс Почты.
   Основной пароль от аккаунта в программу не вводите.
4. Введите пароль приложения в поле «Пароль приложения Яндекс Почты».
5. Нажмите «Сохранить настройки», затем «Проверить Диск и почту (без отправки)».
   Сервер SMTP фиксирован: smtp.yandex.ru:465 с проверкой TLS-сертификата.
   Отправка писем не начинается от этой проверки.

ШАГ 5. ПОДКЛЮЧЕНИЕ И ТЕСТ
1. Нажмите «Запустить бота», затем «Подключить сотрудников».
2. Сначала сами отправьте НОВОМУ боту показанную команду /owner с вашим кодом.
3. Выдайте сотрудникам команду /join с кодом сотрудников и названием филиала.
   Код владельца не передавайте. Подключённые сотрудники смогут видеть названия
   всей очереди, удалять любой ещё не отправленный файл и запускать общую отправку.
4. Выберите «Широкоформатная печать», затем «Загрузить файл».
   Загрузите безопасный тестовый TIF как документ, без сжатия.
   Файл принят только после ответа «Сохранён». До этого дождитесь скачивания.
5. Проверьте кнопки просмотра и удаления на ненужном тестовом файле.
6. Загрузите тест снова и нажмите «Отправить сейчас».
7. Проверьте письмо в тестовом ящике (включая «Спам»), скачайте ZIP по ссылке,
   распакуйте и откройте TIF. Сравните размер, название и содержимое с оригиналом.
8. Только после успешного теста включите галочку ежедневной отправки в 18:00.
   Адрес партнёра меняется в «Настройках» после остановки обработчика.

РАБОЧИЙ РЕЖИМ
• Один компьютер работает каждый день с 10:00 до 20:00; он должен оставаться
  включённым с интернетом и без сна, пока вся отправка не завершится.
• 18:00 — начало подготовки, а не гарантия доставки письма ровно в эту секунду.
  Передача нескольких больших файлов может занять время.
• Файлы, отправленные в Telegram начиная с 18:00 МСК, относятся к следующему дню.
  Кнопка срочной отправки может отправить их раньше, по вашему действию.
• Новые файлы после нажатия «Отправить сейчас» остаются для следующей отправки.
• При включении после пропущенного времени автоматическая отправка накопленной
  очереди происходит после 18:00; если запустили утром — ждёт 18:00 либо команды.
• Закрытие окна останавливает обработчик. Сворачивание не останавливает его.
• «Автозапуск при входе Windows» добавляет запуск только для текущего пользователя.
  Это не служба: до входа пользователя программа не работает. Повторное нажатие
  позволяет отключить автозапуск. Не перемещайте папку программы после включения.
• Telegram не гарантирует бессрочное хранение неполученных обновлений для бота.
  После длительного отключения проверяйте подтверждение каждого файла «Сохранён».
• При сетевой ошибке скачивание и подготовка повторяются. Если скачивание
  исчерпало попытки, удалите проблемную запись и отправьте исходный документ заново.
• Если SMTP-сервер мог принять письмо, но ответ потерялся, повтор остановится.
  Проверьте ящик и нажмите в программе «Проверить неопределённое письмо».
  Отмечайте «Нет» только после проверки — ручной повтор может создать дубль.
• Ключи настроек шифруются DPAPI текущего пользователя Windows. Сессия Telegram
  хранится в отдельной SQLite-базе в защищённой папке этого пользователя.
  Не публикуйте и не пересылайте папку данных, настройки или файл сессии.
• Настройки и очередь: %LOCALAPPDATA%\CloudshopPrintDispatch.
  Открыть можно кнопкой в программе. Не удаляйте SQLite-файлы очереди или сессии.
• Резервную копию папки данных делайте только при остановленном обработчике.
  DPAPI-настройки не переносятся автоматически на другого пользователя/компьютер.

ЧТО ПРОВЕРЕНО ПРИ ПОДГОТОВКЕ
Локальные автоматические тесты: файл 500 МиБ, сохранение оригинальных байтов,
совпадающие названия, граница 18:00, удаление во время загрузки ZIP, запрет
удаления после начала SMTP, остановка повторов при неоднозначном ответе,
восстановление очереди после перезапуска, отсутствие повторных уведомлений владельцу.
Тесты сетевых сценариев используют подставные Диск/SMTP/Telegram.
Windows DPAPI, автозапуск и живая отправка с ваших аккаунтов в этой среде
не проверялись: их проверяем на выбранном Windows-компьютере перед работой.
TEST.cmd запускает локальные тесты, не отправляя писем и не подключаясь к аккаунтам.
