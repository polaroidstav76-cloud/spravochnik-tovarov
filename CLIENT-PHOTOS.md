# Фотографии клиентов

Клаудшоп → **Ссылка для фото**. Сотрудник указывает телефон и, по желанию, номер заказа. Филиал берётся из открытой смены; администратор без смены выбирает филиал вручную.

## Однократное подключение

Администратор открывает **Ссылка для фото → Подключить Яндекс Диск** и вставляет OAuth-токен аккаунта с нужным объёмом. Нужны права чтения, записи и информации о Диске. Токен вводится только в защищённое поле на сайте, не в переписку и не в config.js. Он проверяется на сервере и хранится в Supabase Vault. Почту отправителя в программе «Перезаказы» менять не нужно. Программа на Windows для этой функции не нужна.

Файлы хранятся в `Cloudshop-Client-Photos/<случайный идентификатор заказа>/`. Смена аккаунта с уже сохранёнными фото блокируется: сначала нужен перенос. Обновление токена того же аккаунта разрешено.

## Клиент

- По личной ссылке имя и телефон повторно не запрашиваются.
- Для одного размера размер не вводится. Для разных размеров — отдельные группы со свободным названием.
- Загрузка трёх оригиналов параллельно, реальный прогресс PUT, два автоматических повтора. Файлы с ошибкой можно повторить вручную либо исключить; сохранённые оригиналы не удаляются.
- Завершение недоступно, пока есть незавершённые файлы. После завершения можно нажать «Добавить ещё фото».
- Комментарий сохраняется и в базе, и в текстовом файле внутри папки заказа.
- ZIP получается официальным API публичной папки Яндекс Диска. Если сервис не выдаёт прямой ZIP, открывается папка с кнопкой «Скачать всё». Сам клиентский адрес остаётся постоянным; временная ссылка скачивания получается заново.

Нет уменьшения, перекодирования, canvas, исправления EXIF или обрезки. XHR отправляет исходный `File` целиком. Скорость зависит от сети клиента и Яндекс Диска; iPhone может приостановить передачу при сворачивании браузера. До завершения держать страницу открытой. После закрытия страницы уже принятые файлы сохраняются, незавершённые нужно выбрать снова (имя и размер сопоставляются с ожидающими файлами).

Технические ограничения: 512 МиБ на фото, 5000 фото и 4,5 ГБ на ссылку, до 100 групп размеров. Лимит общего объёма выбран ниже ограничения ZIP папок Яндекс Диска 5 ГБ. При большем объёме создаётся ещё одна ссылка. Поддержаны JPEG, PNG, HEIC/HEIF, TIFF, WEBP, AVIF, BMP, DNG/CR2/NEF/ARW. Оригиналы с одинаковыми именами получают разные префиксы и не перезаписывают друг друга.

## QR филиала и история

В окне «Ссылка для фото» можно скачать PNG QR-кода каждого действующего филиала. Это постоянный адрес `photos.html?branch=...`. Клиент указывает телефон и WhatsApp либо MAX, затем получает отдельную личную ссылку. Это не отправляет сообщения в мессенджеры автоматически.

История показывает последние 200 ссылок; поиск по телефону/номеру работает по всей доступной истории. Сотрудник видит свои ссылки и ссылки текущего филиала, администратор — все. Новые завершённые загрузки отмечаются в Клаудшопе при открытом сайте (проверка раз в 30 секунд). QR-заказы помечены «ОФЛАЙН-ЗАКАЗ». Ссылку можно скопировать в переписку.

Срока действия и автоматической очистки нет. Доступ к заказу есть у любого обладателя личной ссылки; её не следует публиковать. Ключ находится после `#`, не уходит в запросы GitHub Pages и реферер. Публичный клиент не имеет доступа к общему списку, телефону полностью, OAuth-токену или внутренним путям. Сервер проверяет сотрудника через Auth, настройки — только для активного администратора. Для QR есть ограничение создания заявок по хешу адреса сети; оригиналы не проходят через Edge Function.

## Проверка

- `node --check photo-common.js` / `photos.js` / `photo-staff.js`
- `tests/photo-links-rollback.sql` — транзакционная проверка разделения клиентов, прав, повторов, групп, блокировки завершения, добавления фото и сохранности оригиналов; завершается ROLLBACK.
- `tests/photo-links-browser.cjs` — Playwright + Chromium, локальный HTTP-сервер, перехваченный Disk API. Проверяет телефон/QR, несколько размеров, 100 файлов, максимум три параллельные передачи, побайтовое равенство исходника, мобильную вёрстку, повторное добавление и окно сотрудников. Зависимости для теста: playwright 1.58.2; браузер `/usr/bin/chromium`. `PHOTO_TEST_URL` меняет адрес локального сервера.
- Настоящие загрузка/ZIP требуют однократного подключения владельцем его Диска. Тестовые подмены не подтверждают доступ к реальному аккаунту, CORS загрузочного сервера или фактическую скорость сети клиента.

Сервер: `supabase/functions/photo-links/index.ts`, verify_jwt=false, собственная проверка JWT/личного ключа. Метаданные: `client_photo_links.sql`, закрытая схема `photo_private`; публичная RPC доступна только service_role. Установка через миграции Supabase, публикация страницы через существующий GitHub Pages.
