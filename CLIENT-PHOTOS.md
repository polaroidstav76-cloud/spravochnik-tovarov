# Фотографии клиентов

Клаудшоп → **Ссылка для фото**. Сотрудник указывает телефон и, по желанию, номер заказа. Филиал берётся из открытой смены; администратор без смены выбирает филиал вручную.

## Однократное подключение

Администратор открывает **Ссылка для фото → Подключить Яндекс Диск** и вставляет OAuth-токен аккаунта с нужным объёмом. Нужны права чтения, записи и информации о Диске. Токен вводится только в защищённое поле на сайте, не в переписку и не в config.js. Он проверяется на сервере и хранится в Supabase Vault. Почту отправителя в программе «Перезаказы» менять не нужно. Программа на Windows для этой функции не нужна.

Файлы хранятся в `Cloudshop-Client-Photos/<случайный идентификатор заказа>/`. Смена аккаунта с уже сохранёнными фото блокируется: сначала нужен перенос. Обновление токена того же аккаунта разрешено.

## Клиент

- По личной ссылке имя и телефон повторно не запрашиваются.
- Для одного размера размер не вводится. Для разных размеров — отдельные группы со свободным названием.
- Параллельная загрузка выбранных оригиналов, реальный прогресс PUT, два автоматических повтора. Файлы с ошибкой можно повторить вручную либо исключить; сохранённые оригиналы не удаляются.
- Завершение недоступно, пока есть незавершённые файлы. После завершения можно нажать «Добавить ещё фото».
- Комментарий сохраняется и в базе, и в текстовом файле внутри папки заказа.
- ZIP получается официальным API публичной папки Яндекс Диска. Если сервис не выдаёт прямой ZIP, открывается папка с кнопкой «Скачать всё». Сам клиентский адрес остаётся постоянным; временная ссылка скачивания получается заново.

Для оригиналов нет уменьшения, перекодирования, исправления EXIF или обрезки. Кадрирование выполняется только по явному выбору клиента и создаёт отдельный JPG; оригинал остаётся неизменным. XHR отправляет исходный `File` целиком. Скорость зависит от сети клиента и Яндекс Диска; iPhone может приостановить передачу при сворачивании браузера. До завершения держать страницу открытой. После закрытия страницы уже принятые файлы сохраняются, незавершённые нужно выбрать снова (имя и размер сопоставляются с ожидающими файлами).

Технические ограничения: 512 МиБ на фото, 5000 фото и 4,5 ГБ на ссылку, до 100 групп размеров. Лимит общего объёма выбран ниже ограничения ZIP папок Яндекс Диска 5 ГБ. При большем объёме создаётся ещё одна ссылка. Поддержаны JPEG, PNG, HEIC/HEIF, TIFF, WEBP, AVIF, BMP, DNG/CR2/NEF/ARW. Оригиналы с одинаковыми именами получают разные префиксы и не перезаписывают друг друга.

## QR филиала и история

В окне «Ссылка для фото» можно скачать PNG QR-кода каждого действующего филиала. Это постоянный адрес `photos.html?branch=...`. Клиент указывает телефон и WhatsApp либо MAX, затем получает отдельную личную ссылку. Это не отправляет сообщения в мессенджеры автоматически.

История показывает последние 200 ссылок; поиск по телефону/номеру работает по всей доступной истории. Сотрудник видит свои ссылки и ссылки текущего филиала, администратор — все. Новые завершённые загрузки отмечаются в Клаудшопе при открытом сайте (проверка раз в 30 секунд). QR-заказы помечены «ОФЛАЙН-ЗАКАЗ». Ссылку можно скопировать в переписку.

Срока действия и автоматической очистки нет. Доступ к заказу есть у любого обладателя личной ссылки; её не следует публиковать. Ключ находится после `#`, не уходит в запросы GitHub Pages и реферер. Публичный клиент не имеет доступа к общему списку, телефону полностью, OAuth-токену или внутренним путям. Сервер проверяет сотрудника через Auth, настройки — только для активного администратора. Для QR есть ограничение создания заявок по хешу адреса сети; оригиналы не проходят через Edge Function.

## Проверка

- `node --check photo-common.js` / `photos.js` / `photo-staff.js`
- `tests/photo-links-rollback.sql` — транзакционная проверка разделения клиентов, прав, повторов, групп, блокировки завершения, добавления фото и сохранности оригиналов; завершается ROLLBACK.
- `tests/photo-links-browser.cjs` — Playwright + Chromium, локальный HTTP-сервер, перехваченный Disk API. Проверяет телефон/QR, несколько размеров, 100 файлов, максимум три параллельные передачи, побайтовое равенство исходника, мобильную вёрстку, повторное добавление и окно сотрудников. Зависимости для теста: playwright 1.58.2; браузер `/usr/bin/chromium`. `PHOTO_TEST_URL` меняет адрес локального сервера.
- Настоящие загрузка/ZIP требуют однократного подключения владельцем его Диска. Тестовые подмены не подтверждают доступ к реальному аккаунту, CORS загрузочного сервера или фактическую скорость сети клиента.

Сервер: `supabase/functions/photo-links/index.ts`, verify_jwt=false, собственная проверка JWT/личного ключа. Метаданные: `client_photo_links.sql`, закрытая схема `photo_private`; публичная RPC доступна только service_role. Установка через миграции Supabase, публикация страницы через существующий GitHub Pages.

## Самостоятельное кадрирование

Кнопка «Хочу кадрировать сам» включает необязательное редактирование каждого снимка. Размеры 10×15, 15×21, 21×30, 30×40 см; горизонтальный исходник автоматически получает горизонтальную рамку. Есть поворот рамки, поворот фото на 90°, масштаб, перетаскивание мышью/пальцем, pinch-zoom и стрелки клавиатуры.

Семь полароидов используют точную геометрию `foto-26-site/src/lib/polaroidFrames.ts`: 6×9, 8×8, 10×10, 10×12, 10×15, 7×10 (3 мм), 10×15 (3 мм). Сохраняется отдельная карточка по границам реза, как в предпросмотре сайта, без компоновки двух карточек на печатный лист. Поэтому фактические размеры карточек соответствуют шаблонам сайта (например, 6×9 — 653×980 px). Подписи и парная раскладка на лист в этот редактор не добавлены.

Экспорт: JPG с максимальным качеством кодировщика, sRGB canvas, 300 dpi в JFIF и точными размерами в пикселях. Например, 10×15: 1181×1772, 30×40: 3543×4724. Сервер проверяет сигнатуру JPG, размеры SOF, плотность 300 dpi и размер файла, затем публикует копию в отдельной папке `Cloudshop-Client-Ready`. Неизменяемые версии лежат в `Cloudshop-Client-Crops`. Повторное редактирование заменяет текущую печатную копию, сохраняя оригинал и предыдущие версии. Публикация одного файла защищена короткой блокировкой; архив готовых фото недоступен, пока копирование не завершено.

Кнопка «Готовые JPG ZIP» скачивает только сохранённые кадрированные версии. Остальные снимки и все исходники доступны отдельной кнопкой «Оригиналы ZIP». Можно вернуть конкретное фото к оригиналу; готовая копия переносится в историю, исходник не удаляется. Незавершённое кадрирование блокирует завершение заказа, пока клиент не сохранит JPG либо не выберет оригинал.

Положение/масштаб/формат автоматически сохраняются в серверный черновик с проверкой версии и в localStorage. Выбранные исходники и незагруженные JPG — в IndexedDB. После закрытия и открытия браузера по той же ссылке ожидающие исходники автоматически продолжат загрузку с теми же идентификаторами, а редактор восстановит черновик. При конфликте вкладок нельзя молча перезаписать более новую версию. При очистке данных сайта, приватном режиме или исчерпании локального места восстановление ещё не отправленных данных браузером не гарантируется; уже загруженные оригиналы и серверные черновики от этого не зависят. Если локальное сохранение не удалось, страница явно просит не закрывать браузер до конца загрузки.

HEIC/TIFF/RAW сохраняются оригиналами; кадрирование возможно, если браузер декодирует формат. В остальных случаях редактор сообщает о необходимости JPG/PNG, не удаляя исходник. Низкое исходное разрешение отмечается до экспорта; установка 300 dpi не восстанавливает отсутствующие детали.

Проверки: `tests/photo-crop-browser.cjs` (полное закрытие Chromium, восстановление несинхронизированного черновика и исходника, прерванная загрузка, повороты, обычный/полароид JPG, плотность и размеры, мобильная вёрстка); `tests/photo-crop-rollback.sql` (черновики, конфликты, физические размеры, блокировка публикации и сохранение истории); обновлённый `tests/photo-links-edge.cjs` проверяет серверный отказ JPG с неправильным dpi.


## Обновление подготовки фотографий 22.11.2026

- Кнопка «Обрезать фото и добавить поля» только в процессе добавления фото. На выборе режима и после завершения загрузки отдельного предложения обработки нет.
- Крупная сетка превью, без обязательных названий. Загружаемые фото тоже видны. Превью готовых фото появляются по мере прокрутки, одновременно обрабатываются максимум два; это не запускает сотню скачиваний сразу.
- Редактор позволяет переходить назад/вперёд. На сенсорном экране при масштабе 1 горизонтальный жест перелистывает; перетаскивание и pinch управляют положением и масштабом, колёсико мыши меняет масштаб. При перелистывании и «Готово» JPG публикуется автоматически, сбой оставляет редактор открытым и черновик доступным.
- Белые и размытые поля, размеры из списка или собственный размер 1–42 см по каждой стороне (до 5000 пикселей при 300 dpi). Полароиды сохранены. Оригинал можно оставить без обработки или начать обработку заново.
- Общий размер и режим полей применяются последовательно, с отдельным положением каждого фото. Новые готовые фото получают общие настройки после закрытия редактора. Завершение заказа блокируется до применения; при ошибке есть повтор.
- Подготовка первых фото доступна, пока остальные оригиналы загружаются. Оригиналы передаются без изменения байтов; файлы обработки — отдельные JPG 300 dpi.
- Открытие офлайн-заказа — обычная ссылка. После запроса ZIP рядом появляется прямая ссылка на скачивание, работающая и при блокировке popup.

Серверная миграция: `photo_crop_flow.sql` (новые размеры и проверка режимов). Edge Function не меняется. Проверены SQL-тесты с откатом, собственный размер 12×18, недопустимый размер, браузерные сценарии сохранения, белых/размытых полей, колёсика, перехода, общей настройки и применения к позднему файлу, QR и архивы офлайн-заказов. Тестовые HTTP-запросы Диска подменены; реальную скорость и скачивание из аккаунта проверяет владелец на своей ссылке.


Уточнение 22.11.2026: в карточке истории Клаудшопа оставлено только «Открыть фото». Кнопки скачивания оригиналов/JPG и дополнительные ссылки скачивания удалены; архивы скачиваются на странице по личной ссылке. Копирование новой ссылки при её создании сохранено.


## Упрощённый редактор и фоновое сохранение, 22.11.2026

Редактор открывается нажатием на крупное фото; отдельное предложение ручной обработки удалено. Список размеров один; поля ширины/высоты видны только при выборе «Свой размер». Режимы размещения — кнопки «Без полей», «Белые поля», «Размытые поля». Поверх фото внизу — стрелки и счётчик; стрелки клавиатуры работают в редакторе, кроме ввода в поля, сенсорное перелистывание сохранено. «Начать с оригинала» переименовано в «Вернуть оригинал фото».

Отдельной нижней «Готово» нет. Изменения сохраняются автоматически после паузы; при переходе или верхней «Готово» редактор закрывается немедленно, а JPG продолжает готовиться и передаваться в фоновой очереди. Задания разных фото могут выполняться параллельно; для одного фото записи сериализованы. На странице остаётся статус «Не закрывайте сайт», завершение заказа блокируется, beforeunload предупреждает до окончания операций. Ошибки видны вне закрытого редактора; черновики и промежуточные JPG остаются в IndexedDB для повтора. Оригиналы запускаются на отправку без прежнего ограничения в три работника; реальное число одновременных сетевых соединений определяет браузер.

Проверены: скрытые поля стандартного размера, одна верхняя «Готово», стрелки внутри фото, клавиатурное перелистывание, мгновенное закрытие при искусственно медленной отправке и видимый фоновый статус, восстановление черновика, 300 dpi и исходные байты; 100 файлов запускаются параллельно. Настройки сервера и базы не менялись.
