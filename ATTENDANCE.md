# Включения и опоздания

В админке: «Включения и опоздания». Один основной компьютер на филиал. Windows 10/11, встроенный PowerShell 5.1, без Python и отдельного сервера.

## Подключение

1. Скачайте `downloads/Cloudshop-Attendance-Windows-v1.1.zip`, распакуйте весь архив.
2. В Клаудшопе откройте настройки выбранного филиала, включите учёт, проверьте рабочие часы и дату начала, сохраните.
3. Получите одноразовый код, запустите INSTALL.cmd, разрешите запрос администратора Windows и вставьте код. Код действует 15 минут. В переписку его отправлять не нужно.
4. Нажмите «Обновить» в Клаудшопе: появятся название ПК, версия и время получения данных.

По умолчанию учёт начинается завтра, чтобы не считать день установки полноценным наблюдением. Для проверки можно выбрать сегодня. При изменении часов уже сохранённые дни сохраняют прежнее время начала. Для замены ПК сначала отключите старый в админке. Удаление локальной программы — UNINSTALL.cmd.

## Учёт

Первое включение Windows за местный день — время открытия. Часовой пояс сервера и графика — Москва. Время берётся из Kernel-Boot 27 (включая Fast Startup), с резервным чтением Win32_OperatingSystem. Windows должна показывать правильное время. Перезагрузки не сдвигают первый приход. Без сети очередь сохраняется на диске и передаётся начиная с самого раннего события.

Основной сотрудник — первая клетка филиала в опубликованном графике. Помощник не участвует в персональном рейтинге: общий компьютер не позволяет определить время его прихода. Если основной сотрудник не определён однозначно, история хранится без персонального сравнения. График фиксируется в записи дня при её создании. Спорные дни можно исключить с причиной; это действие записывается в аудит.

Рейтинг считает только дни с известным сотрудником и фактическим первым включением после даты начала учёта. Опоздание — полные минуты после начала работы. Нет данных, не выключенный на ночь ПК, неопубликованный график и исключённые дни не увеличивают число опозданий.

## Telegram

Используется существующий бот Клаудшопа и активный личный получатель сводок (сейчас Рустам). Только:

- первое включение в рабочий день;
- отсутствие данных о включении через две минуты после начала работы (со словами о возможном отсутствии интернета, без утверждения о доказанном опоздании).

Никаких сообщений о выключении, работе после закрытия, проверках связи и потере интернета. После окончания рабочего дня уведомления не отправляются. При перезагрузке не возникает новой карточки включения. Технический heartbeat раз в пять минут нужен только для различения оставленного на ночь ПК и нового старта.

## Техническая проверка

- SQL-тесты проверены в транзакции с откатом, планировщик — с явным dry-run: он не читает Telegram-токен и не выполняет HTTP-запросы.
- Проверены одноразовые коды, отзыв устройств, хеширование токенов, первый старт, офлайн-порядок, основная клетка графика, опоздания, исключения, запрет обычным сотрудникам и отсутствие прав anon.
- Windows CI: синтаксис PowerShell 5.1, чтение настоящего времени загрузки Windows, DPAPI, очередь с одним/несколькими событиями, пустая очередь и определение задания SYSTEM.
- JS: ограничения админки, экранирование имён, сводка, исключение неизвестных дней, копирование кода и очистка при смене аккаунта. Edge: метод, размер запроса и обязательная авторизация устройства.

Локально хранится зашифрованный DPAPI токен, доступный SYSTEM и администраторам ПК. На сервере — только его SHA-256. Программа не читает файлы сотрудника, не делает снимки экрана и не управляет печатью.

## Исправление 1.1 от 19.11.2026

Раньше процесс сохранял время загрузки в переменную один раз. После сна, гибернации или быстрого запуска процесс мог продолжить работу со вчерашним временем. Теперь журнал Windows перечитывается каждую минуту: Kernel-General 12/13, Kernel-Boot 27, Kernel-Power 41/42/107/109 и Power-Troubleshooter 1. Даты загрузок и выходов из сна обновляют первое начало рабочего дня, завершения и сон сохраняются отдельно. События дедуплицируются на устройстве и сервере.

В истории добавлены завершения работы Windows и список событий. При аварийном пропадании питания точное время отключения не утверждается. Отсутствие связи не считается выключением. Старое сообщение «не выключался на ночь» заменено на «новый запуск не подтверждён». Выключения никогда не создают Telegram-уведомления.

События завершения могут быть переданы только после следующего запуска: сеть и обработчик во время выключения уже могут быть недоступны. Обновление считывает доступную историю за 30 дней и исправляет пропущенные запуски по реальным событиям Windows. При отсутствии событий время не выдумывается.

Для обновления распакуйте ZIP 1.1 и запустите UPDATE.cmd от администратора. При существующем device.bin код не запрашивается, токен не переписывается, привязка к филиалу сохраняется. Прежнюю программу перед обновлением не удалять. Версия в админке после обновления — 1.1.0.
