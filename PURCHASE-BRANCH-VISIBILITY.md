# Закупки сотрудников по филиалам

Сотрудник видит текущие заявки своего филиала: открытой смены, а при её отсутствии — последней смены. Сервер проверяет связку staff_accounts.person_id → sales_employees → sales_shift_employees; переданный ID чужой смены доступа не даёт. Прямой SELECT stock_requests и старый stock_purchase_live также ограничены, удаление чужой заявки запрещено. После закрытия смены доступен филиал последней подтверждённой смены сотрудника. Переданный ID чужой или более старой закрытой смены доступа не даёт.

Кнопка «Последняя заявка» показывает одну последнюю завершённую администратором закупку: состояние открытых заявок своего филиала до оформления, фактически заказанные ему позиции и дату по Москве. Следующая общая закупка заменяет прежнюю, в том числе когда для филиала ничего не заказано. Незакупленные заявки остаются в текущем списке. Администратору доступен прежний общий список и полная история.

Для старых закупок есть итоговые строки с названием филиала, но нет снимка исходной заявки: интерфейс сообщает об этом явно. Новые строки дополнительно содержат branch_id/request_id, переименование филиала не нарушает фильтрацию.

Миграция: stock_purchase_branch_visibility.sql. Проверки: tests/purchase-branch-visibility.cjs, tests/purchase-branch-visibility-rollback.sql; также purchase-simple, purchase-delete, purchase-rounds. SQL-проверка выполняется в ROLLBACK: отправка Telegram не происходит, поскольку очередь pg_net работает после commit.

Исправление просмотра после закрытия смены: `stock_purchase_closed_shift_view.sql`. Существующие заявки не изменяются и не создаются повторно.
